## Codebase Patterns
- Prisma 7 no longer accepts `url` in schema.prisma datasource (neither hardcoded nor env-based); URL goes to `prisma.config.ts` for CLI
- Prisma 7 runtime client REQUIRES a driver adapter — use `@prisma/adapter-libsql` with `new PrismaLibSql({ url })` passed to `new PrismaClient({ adapter })`; `new PrismaClient()` alone throws PrismaClientInitializationError
- `PrismaLibSql` takes a `Config` object `{ url }` directly (not a `Client` instance from `createClient`)
- Prisma config file is `prisma.config.ts` (not just schema); db URL set there as `file:./prisma/dev.db` for CLI operations
- next-pwa requires CommonJS config — rename `next.config.mjs` to `next.config.js` and use `module.exports = withPWA(config)` (ESM `.mjs` does not work with next-pwa require())
- `node_modules/.bin/tsc` may be a copy (not symlink) breaking execution; fix with `ln -s ../typescript/bin/tsc node_modules/.bin/tsc`
- When scaffolding with create-next-app in a temp dir and copying files, use `cp -r /tmp/pkg/.` NOT with `--preserve` to avoid copying broken symlinks, then do `npm install` fresh to regenerate node_modules
- The copied .git directory from create-next-app initializes on `main`; create `ralph/phase-1-foundation` branch afterwards
- Run `npx prisma generate` after any `npm install` or after adding new model fields; without it, Prisma returns `any` types and tsc will fail on callback parameter types
- lib/prisma.ts exports named `prisma` (not default); always use `import { prisma } from '@/lib/prisma'`
- Use Prisma `select` (not `include`) to exclude sensitive fields from API responses naturally; avoids post-processing destructuring hacks
